# Gemini Web API Bridge

📣 简介 / Introduction

Gemini Web API Bridge 是一个允许编程工具（如 Pi Agent）通过已登录的 Gemini 网页版 (gemini.google.com) 与 Gemini 2.5 Pro 模型进行双向交互的系统。它不需要 Google AI Studio API Key。相反，它通过一个 Chrome 扩展程序实时注入 Prompt、运行对话，并捕获网页上的响应回传给请求方。

该系统还支持工具调用 (Tool Use / Function Calling)，允许 Gemini 通过特定文本标记（或 Pi 兼容的 JSON payload）触发客户端工具（如编辑文件、运行 bash 命令）的执行。

Gemini Web API Bridge is a system that allows programming tools (like Pi Agent) to interact bidirectionally with the Gemini 2.5 Pro model via an already logged-in Gemini web interface (gemini.google.com).

It does not require a Google AI Studio API Key. Instead, it utilizes a Chrome extension to inject prompts, run conversations, and capture the on-page responses to send back to the requester in real-time.

The system also supports Tool Use (Function Calling), allowing Gemini to trigger the execution of client-side tools (e.g., editing files, running bash commands) via specific text markers (or Pi-compatible JSON payloads).

✨ 核心特性 / Key Features

零 API Key 依赖 / Zero API Key Dependency: 完全基于已登录的 Gemini 网页版用户会话。Uses the logged-in Gemini web user session.
双向通信 / Bidirectional Communication: 支持 Pi Provider 注册并与 Gemini 进行流式/非流式对话。Supports Pi Provider registration for streaming/non-streaming chat with Gemini.
工具调用支持 / Tool Use Support: 能够解析并执行 Gemini 生成的工具调用请求。Able to parse and execute tool call requests generated by Gemini.
鲁棒的 JSON 解析 / Robust JSON Parsing: Provider 端具备多层兜底的坏 JSON 修复能力，处理 Gemini 网页端生成的非标准或截断的 JSON。The Provider-side has multi-layered bad JSON repair capabilities to handle non-standard or truncated JSON generated by the Gemini web interface.
自动 Content Script 注入 / Automatic Content Script Injection: 扩展程序在与 Gemini 标签页通信失败时，会自动尝试向该标签页程序化注入必要的 content scripts，解决扩展重载后旧页面失效的问题。If communication with a Gemini tab fails, the extension automatically attempts to programmatically inject the necessary content scripts, solving the issue of old pages failing after an extension reload.
长轮询架构 / Long-Polling Architecture: 零 WebSocket 依赖，通过 HTTP 长轮询实现高效的 pending prompt 拉取。Zero WebSocket dependency; uses HTTP long-polling for efficient pending prompt pulling.
中文友好 / Chinese Friendly: 系统答复均为中文。System responses are all in Chinese.

🛠️ 系统架构 / System Architecture

该系统由三个核心组件组成：

Bridge Server (Node.js): 充当中转站。它接收来自 Pi Provider 的 HTTP 请求，将其排队为 pending prompt。Chrome 扩展通过长轮询拉取 pending prompt，Gemini 生成结果后，扩展将结果 POST 回 Server。
Chrome Extension (WXT): 负责与 Gemini 网页交互。它轮询 Server 获取 pending prompt，使用 browser.scripting.executeScript 将 prompt 注入网页对话框并模拟发送。随后捕获 .textContent 响应文本（处理坏 JSON）发送回 Server。它还包括 background.ts 用于自动注入和 popup 界面。
Pi Provider Extension: 用于注册到 Pi Coding Agent。它实现了 streamSimple 接口，将 Pi 的消息转换为 Bridge 请求，并将 Server 返回的响应文本鲁棒地解析为 Pi 的 content blocks（Thinking、TextContent、ToolCall）。

The system consists of three core components:

Bridge Server (Node.js): Acts as the relay station. It receives HTTP requests from the Pi Provider and queues them as pending prompts. The Chrome extension pulls pending prompts via long-polling, and after Gemini generates a result, the extension posts the result back to the server.
Chrome Extension (WXT): Responsible for interacting with the Gemini web page. It polls the server for pending prompts, uses browser.scripting.executeScript to inject the prompt into the web chat box and simulate a send. It then captures the .textContent response text (handling bad JSON) to send back to the server. It also includes background.ts for automatic injection and a popup interface.
Pi Provider Extension: Used for registration with the Pi Coding Agent. It implements the streamSimple interface, converts Pi's messages into Bridge requests, and robustly parses the response text returned by the server into Pi's content blocks (Thinking, TextContent, ToolCall).

🚀 快速验证端到端工具调用 / Quick End-to-End Tool Use Verification

为了快速验证整套系统的工具调用链路是否通畅，可以尝试以下几个递进的测试场景：

多轮 Agent Loop 测试： 帮我看看 package.json 里的 name 字段是什么，然后在 README.md 第一行加上这个名字
预期结果：
Gemini 生成读文件工具。Pi 执行工具，得到 name = gemini-web-api-bridge。
Pi 将结果回传。Gemini 接收结果，生成精确编辑工具。
Pi 执行编辑，更新 README.md。
Pi 发送编辑结果回 Gemini → Gemini 确认完成。
如果两轮工具调用都能跑通，说明系统已完全稳健可实际使用。

复杂命令转义测试： 帮我统计 server.cjs 有多少行代码 或 用 bash 列出当前目录下所有 .ts 文件的行数
预期结果： 验证系统对特殊字符（如换行符、引号）在 JSONPayload 中的转义是否稳定。

代码生成测试： 在项目根目录创建一个 hello.ts，写一个函数输出斐波那契数列前 10 项

To quickly verify that the entire tool call chain of the system is functional, you can try the following progressive test scenarios:

Multi-Round Agent Loop Test: Show me what the name field is in package.json, then add this name to the first line of README.md

Pi sends the edit result back to Gemini -> Gemini confirms completion.
